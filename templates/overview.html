📘 Project Overview & Machine Learning Architecture

A multi-engine Intrusion Detection System that combines flow-level Random Forest inference with C2, DNS tunneling, exfiltration, and risk-scoring logic. Offline NSL-KDD results, controlled detector tests, and live telemetry are reported separately so implementation capability is not confused with real-world validation.

🤖 Machine Learning Models & Algorithm Details

The project evaluated multiple statistical and ensemble learning algorithms before selecting the production ensemble:

🌲 Random Forest

PRODUCTION

How it works: An ensemble of 300 de-correlated decision trees uses bootstrap aggregation. Tree votes produce an attack probability for each five-feature flow; the risk engine then combines that signal with behavioral evidence.

  • 300 Estimators, Balanced class weighting
  • Min samples leaf = 2, Threshold = 0.50
  • Model probability and risk score are reported separately
Accuracy75.59%
Precision95.94%
Recall59.64%
F1 Score73.56%

BENCHMARK

📚 Training Dataset & Feature Engineering

The model was trained and evaluated on the NSL-KDD network intrusion dataset. NSL-KDD is an offline benchmark; it does not establish live-network accuracy or cross-dataset generalization.

TRAINING DATASET KDDTrain+.txt 125,973 Samples
VALIDATION SPLIT KDDTrain+ 80/20 25,195 Samples
TEST BENCHMARK Holdout Test 22,544 Samples
DECISION THRESHOLD 0.50 Threshold Fixed 0.50 operating point

5 Flow-Level Features Extracted in Real Time:

1. duration Elapsed time in seconds between flow SYN/first packet and connection termination or timeout.
2. protocol_type Encoded transport protocol (TCP, UDP, ICMP) mapped to model label encoding.
3. src_bytes Total payload and header bytes transferred from client/initiator to server.
4. dst_bytes Total payload and header bytes transferred from server back to client.
5. count Recent connections to the same destination host within a two-second context window; packet count is tracked separately.

🛡️ Specialized Cyber Threat Engines (Problem Statements)

The system supplements the flow classifier with three behavioral detectors and one risk-correlation engine. Their current quantitative evaluation is based on limited controlled fixtures.

📡 Encrypted C2 Beaconing (Problem 1)

Looks for repeated, low-jitter connection timing and lightweight heartbeat-like flows, including encrypted traffic where payload inspection is unavailable.

  • Tracks inter-arrival interval time ($\Delta t$) per (src, dst, port)
  • Calculates coefficient of variation ($CV = \sigma / \mu$) to measure jitter
  • Flags machine-driven timers ($CV \le 0.15$) with lightweight heartbeat payloads (< 4KB)

🌐 Covert DNS Tunneling (Problem 2)

Scores DNS names for entropy, length, label structure, and encoded-looking payload patterns while allowing configured provider suffixes.

  • Calculates mathematical Shannon Entropy ($H \ge 3.6$ - $4.0$)
  • Measures subdomain label length (> 35 chars) and total query length (> 60 chars)
  • Hex & Base64 regex pattern checks with cloud provider whitelisting

🚀 Data Exfiltration Detector

Scores upload-heavy flows using transfer size, direction asymmetry, velocity, and cumulative host egress.

  • Analyzes directional byte asymmetry ($src\_bytes \gg dst\_bytes$, $\ge 15\times$)
  • Flags burst velocity exceeding 500 KB/s - 1 MB/s
  • Tracks cumulative 60-second host egress spikes (> 5 MB bursts)

⚖️ False-Positive Risk Engine (Problem 4)

Correlates signals over a 120-second stateful sliding window to prioritize alerts and dampen isolated weak ML anomalies.

  • De-escalates isolated single-packet anomalies (< 65% probability)
  • Escalates score with persistent suspicious observations
  • Produces unified 0–100 threat score and categorized severity bands
